# Проверка и дополнение списка Classics по одному языку

Вы — главный редактор серии классики в оригинале для изучающих язык. Серия «Библиотека Classics» издаёт public domain тексты (полностью, без адаптации) для взрослых, изучающих язык (чаще B1–B2), и для тех, кто «классику не особо любит». Приоритет: увлекательно, комфортно читать изучающему, продаётся (узнаваемые названия + подзабытые жемчужины). Отдельно отмечаются тёплое (`warm`), смешное (`humor`) и подзабытые жемчужины (`gem`). Сборники коротких рассказов (авторские и составительские) приветствуются.

Требования к списку и формат книги — в `classics/tools/SPEC.md` (прочитайте целиком: там правила авторского права на 2026 год по странам и поля записи).

Текущий список — `classics/data/<code>.json` (100+ записей, файл большой). Не читайте его целиком сразу: получите компактный индекс командой

```bash
node -e "const d=require('/home/user/news_field/classics/data/<code>.json');d.books.sort((a,b)=>a.tier-b.tier||a.id-b.id).forEach(b=>console.log([b.id,'T'+b.tier,b.title,b.author,b.years,b.published,b.form,b.length,b.level,(b.warm?'W':'')+(b.humor?'H':'')+(b.gem?'G':''),b.rights].join(' | ')));d.bundles.forEach(x=>console.log('BUNDLE',x.name,JSON.stringify(x.ids)))"
```

а отдельные записи смотрите точечно (`node -e` с фильтром по id).

## Что сделать

### 1. Проверка (каждая запись)
- **Факты:** годы жизни автора, год публикации, форма, объём, сюжет в `summary` (нет ли выдуманных деталей, перепутанных героев, спойлера развязки детектива), состав сборников (существуют ли рассказы с такими названиями у этого автора, верны ли переводы названий).
- **Права:** по правилам SPEC.md. Особое внимание: авторы, умершие после 1935; посмертные публикации; США (опубликовано с 1931 — охрана 95 лет от публикации); Россия (+4 года за работу в годы ВОВ, реабилитированные — от года реабилитации); Испания (+80 для умерших до 1987); Франция (mort pour la France, военные продления); Мексика +100, Колумбия +80. Если издание в 2026 году нельзя выпустить ни на одном крупном рынке — удалить.
- **Метки:** `humor` — только если книга действительно смешная (а не «есть ироничные места»); `warm` — только если уютная/добрая по общему ощущению; `gem` — малоизвестна в России. Снимите лишние метки.
- **Уровень и очередь:** реалистичен ли уровень для оригинала; не стоит ли тяжёлый/архаичный текст в первой очереди, а лёгкий хит — в третьей.
- **Дубли и пересечения:** один и тот же текст в двух изданиях (например, рассказ и сборник, куда он входит) — устраните или явно разведите.
- Для сомнительных фактов можно использовать WebSearch (загрузите через ToolSearch `select:WebSearch`, режим "standard"), но экономно — только по реальным сомнениям в датах/правах.

### 2. Дополнение (главное)
Систематически найдите, чего не хватает, и добавьте **не менее 25 новых изданий** (лучше 30–40), только сильных. Пройдите по осям:
- самые продаваемые и узнаваемые public domain названия этого языка (экранизации, бренды героев, школьная программа страны), которых нет;
- юмор и тёплое — как самые важные для «нелюбителей классики»;
- новые тематические **сборники коротких рассказов** (смешные, страшные, рождественские/святочные, о любви, детективные, о животных, о детстве, о еде, о путешествиях, о городе, «на один вечер»), в том числе межавторские антологии;
- жанры, представленные слабо: детектив, приключения, фантастика, мистика, романтическая комедия, письма/дневники, путевые заметки, пьесы-комедии, сказки для взрослых, мемуары;
- авторы, «впервые свободные» в 2024–2026 годах (умерли 1953–1955) — коммерчески сильный повод;
- женщины-авторы, региональные литературы (для испанского — Латинская Америка, для немецкого — Австрия и Швейцария, для французского — Бельгия, Швейцария, Квебек, для английского — США, Канада, Ирландия, Австралия), подзабытые бестселлеры своего времени.
Новые записи должны быть не хуже существующих по качеству текста: `summary` 2–4 предложения, `why` 2–3 предложения, живо, конкретно, по-русски, без штампов.

### 3. Наборы
Проверьте существующие наборы (логика, нет ли лишних книг). Добавьте 4–8 новых наборов, используя новые книги; можно добавлять книги в старые наборы.

## Формат результата — патч, а не переписывание
Не редактируйте `<code>.json`. Запишите `classics/data/<code>.patch.json`:

```json
{
  "report": "Отчёт по-русски, 6–15 пунктов через \n: что нашли и исправили (с id), что удалили и почему, что добавили (по осям), какие права остаются под вопросом.",
  "fixes": [ {"id": 12, "set": {"years": "1864–1941", "humor": false}, "reason": "кратко"} ],
  "remove": [ {"id": 40, "reason": "кратко"} ],
  "add": [ { "id": 1001, "after": 15, "tier": 1, "...": "все поля книги по SPEC.md" } ],
  "bundle_edit": [ {"name": "точное имя существующего набора", "add_ids": [1001], "remove_ids": [7], "concept": "необязательно — новая формулировка"} ],
  "bundle_add": [ {"name": "...", "concept": "...", "ids": [3, 1001, 1004]} ]
}
```
- Новые книги: `id` от 1001 по порядку. `after` — id существующей или новой книги, за которой поставить новую внутри той же очереди (определяет приоритет); если не указать — в конец очереди.
- В `fixes.set` можно менять любые поля, включая `tier`.
- Проверьте валидность: `node -e "JSON.parse(require('fs').readFileSync('<path>','utf8'))"`.
- В конце ответьте 3–5 строками: сколько исправлений, удалений, добавлений, новых наборов и главное из отчёта.
